```solidity
struct Cut {
    bytes32 cL;
    bytes32 cR;
    bytes32 attestationHash;
    uint64 blockB;
    uint64 publishedAt; // != 0 <=> el corte existe
    uint8[] verdicts;
    uint16[] coverageBps;
}

function getCut(bytes32 corteId) external view returns (Cut memory);
function cutExists(bytes32 corteId) external view returns (bool);
function cutCount() external view returns (uint256);
function latestCorteId() external view returns (bytes32);

uint8 public constant DECLARED_MASK = 0x0F; // bit0=cR, bit1=verdicts, bit2=coverageBps, bit3=attestationHash

event CutPublished(
    bytes32 indexed corteId,
    bytes32 cL,
    bytes32 cR,
    uint64 blockB,
    bytes32 attestationHash,
    uint8[] verdicts,
    uint16[] coverageBps,
    uint64 publishedAt,
    uint8 declaredMask
);
```

Nota: `declaredMask` es siempre `0x0F` en esta fase (constante en el contrato, no cambia por corte). No hace falta leerlo del evento: se explica en la UI como texto fijo ("cL está probado on-chain; cR, verdicts, coverageBps y attestationHash son declarados por el publisher").

Deployment address y chainId salen de `deployments.json` (raíz del repo, generado por Phase 2) y/o env `NEXT_PUBLIC_REGISTRY_ADDRESS_*`. Si `deployments.json` no existe todavía al ejecutar este plan, usar únicamente env vars (Phase 2 debe haber corrido antes por `depends_on` de fase).

|----------|--------------|
| Browser ↔ RPC público | Lecturas del Registry sin autenticación; el RPC puede rate-limitear o devolver datos stale |
| `/status/twin-neobank` (público, sin auth) | Cualquiera con la URL accede; no debe filtrar nada que no sea ya público on-chain |
| Env pública (`NEXT_PUBLIC_REGISTRY_*`) | Addresses de Registry expuestas en el bundle cliente (esperado, son públicas por diseño) |
