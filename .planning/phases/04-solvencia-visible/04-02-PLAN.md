<!-- commitment_lib::commit, extraído de
     /Users/francoperez/repos/job/Sobre/sobrecito/circuits/commitment_lib/src/lib.nr -->

```
IV_LEN_SHIFT: Field = 2^64
DOMAIN_USER_COMMITMENT: Field = 0x534f4252454349544f2f555345522f7631  // "SOBRECITO/USER/v1"

iv_for(domain, n_absorbed) = domain * 2^64 + n_absorbed

commit<T>(balances: [Field; T], salt: Field) -> Field:
  sponge = Poseidon2::new(iv_for(DOMAIN_USER_COMMITMENT, T + 1))   // rate=3, capacity=1, state=[0,0,0,iv]
  for t in 0..T: sponge.absorb(balances[t])
  sponge.absorb(salt)
  return sponge.squeeze()
```

El sponge es duplex: `absorb` acumula en `cache` de a 3 elementos y permuta cuando se llena (`std::hash::poseidon2_permutation`, permutación estándar de Noir, no reimplementada — usar la misma primitiva/parámetros que expone la lib JS elegida); `squeeze` suma el cache remanente al state, permuta una vez más y devuelve `state[0]`.

Para T=1 (un solo token, ARGt, caso de la era fixture): `iv = DOMAIN_USER_COMMITMENT * 2^64 + 2` (T+1=2, un balance + un salt).

Ledger de Phase 3 (03-CONTEXT.md D-03): `accounts(user_id, wallet_address, argt_balance, ...)`, `user_id` = DID de Privy. El opening lee `argt_balance` actual de esa tabla.

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser ↔ `/api/cuenta/opening` | Requiere sesión Privy válida; expone balance + salt + commitment de UN usuario, nunca de otro |
| Server ↔ `SOBRECITO_MASTER_HEX` | Secreto que deriva todos los salts; jamás debe llegar al bundle cliente ni a logs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-04-04 | Information Disclosure | `app/api/cuenta/opening/route.ts` | mitigate | El DID se toma exclusivamente del access token de Privy verificado server-side; la ruta nunca acepta un `user_id`/DID como parámetro de query o body, así que un usuario no puede pedir el opening de otro |
| T-04-05 | Information Disclosure | `SOBRECITO_MASTER_HEX` | mitigate | Vive solo en env server de Vercel, nunca en `NEXT_PUBLIC_*`; el salt derivado se calcula y se usa dentro del handler, nunca se loguea el master |
| T-04-06 | Spoofing | Comparación de commitment en el browser | accept | El browser confía en el `commitment` que devuelve el backend como "verdad" a comparar; es la limitación conocida y declarada de D-10 (el binding real es del auditor, no on-chain), comunicada explícitamente en la UI |
