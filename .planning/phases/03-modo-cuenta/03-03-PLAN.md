  <action>
    Crear `lib/cuenta/interest.ts` exportando `accrueInterest()`: con un cliente viem público en Arbitrum, lee `vaultShares = balanceOf(bóveda)` del vault (`VAULT_ARGT_PRIME.address`, función `balanceOf`) y `actual = convertToAssets(vaultShares)`. Dentro de `withTx`: lee `sync_state['convertToAssets_snapshot_value']` (si no existe, `snapshotPrevio = actual`, no acredita nada, solo guarda el snapshot inicial). Calcula `delta = actual - snapshotPrevio`. Si `delta <= 0`: solo actualiza el snapshot (`convertToAssets_snapshot_value/at`), no toca movements. Si `delta > 0`: lee `totalBalances = SUM(argt_balance) FROM accounts`, y para cada cuenta con `argt_balance > 0` inserta `movements(type='interest', amount = floor(delta * argt_balance / totalBalances))` y suma ese monto a `accounts.argt_balance` (el remanente de redondeo queda sin acreditar, D-11). Antes de sobreescribir, mueve el snapshot actual a `convertToAssets_prev_value/at` (para el cálculo de APY en Task 2) y guarda el nuevo `convertToAssets_snapshot_value/at = actual/now()`. `SPREAD_BPS` queda como constante aplicada (`delta = delta * (10000 - SPREAD_BPS) / 10000`, hoy no-op con 0). Crear `app/api/cuenta/interest/route.ts` (`POST`): auth definitiva es la real de Vercel Cron — valida `req.headers.get('authorization') === \`Bearer ${process.env.CRON_SECRET}\`` (así firma Vercel sus crons automáticamente, sin configurar nada aparte de `CRON_SECRET` en env). Aceptar también el header custom `x-cron-secret` como path manual alternativo para curl/demo sin armar el Bearer a mano. 401 si ninguno matchea. Corre `accrueInterest()`, devuelve `{ deltaAccrued, usersCredited }`.
