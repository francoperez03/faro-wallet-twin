<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser ↔ Privy | Credenciales de login (email/Google OAuth) y creación de embedded wallet, manejadas enteramente por el SDK de Privy |
| Browser ↔ RPC público | Lecturas on-chain sin autenticación; RPC público puede rate-limitear o devolver datos stale |
| Env pública (`NEXT_PUBLIC_*`) | El App ID de Privy y las RPC URLs quedan expuestos en el bundle cliente (esperado, son públicos por diseño) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-01-01 | Spoofing | `lib/config/tokens.ts` | mitigate | Addresses hardcodeadas desde SPEC.md §2 verificado por RPC, no desde input de usuario ni de un tercero; único módulo de config evita que otra pantalla use una address distinta por error |
| T-01-02 | Information Disclosure | `NEXT_PUBLIC_PRIVY_APP_ID` | accept | Es una env pública por diseño de Privy (no es secreto); no se expone ninguna clave privada en el cliente |
| T-01-03 | Tampering | `app/(tabs)/home/page.tsx` logout | mitigate | Confirmación explícita antes de `logout()` (copy destructivo del UI-SPEC) para evitar cierres de sesión accidentales |
</threat_model>
